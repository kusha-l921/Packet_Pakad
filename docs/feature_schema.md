# Phase 2 Feature Schema Specification (Version 1.0)

This document specifies the canonical 25-feature schema generated by the Phase 2 flow feature extraction engine (`person2_engine`).

---

## 1. Design Overview

When analyzing encrypted network traffic (e.g. IPsec, ESP, IKE, TLS/HTTPS, WireGuard, or OpenVPN), the underlying application payload is ciphertext. Traditional deep packet inspection (DPI) looking for plaintext signatures is ineffective.

Instead, machine learning models classify traffic patterns using **observable network metadata**:
- Packet sizes and byte distributions
- Directional asymmetries (client request vs. server response ratios)
- Transmission rates (burstiness, packets/sec, bytes/sec)
- Inter-arrival timing (IAT) dynamics

This schema provides **25 deterministic numerical features** in a fixed order. Every feature is guaranteed to be a finite float (no `NaN`, no `Infinity`, no unhandled zero divisions).

## 3. Detailed Feature Definitions

### 1. `total_packets`
- **Mathematical Meaning**: Total count of packets in the bidirectional flow $N = N_{fwd} + N_{bwd}$.
- **How Calculated**: Length of the flow's packet sequence.
- **Why Useful**: Differentiates short transactions (DNS queries, ping, initial handshakes) from long bulk transfers (file transfers, video streams).
- **Edge Cases**: Always $\ge 1$ for any realized flow; `0.0` if empty capture.

### 2. `forward_packets`
- **Mathematical Meaning**: Number of packets traveling in the forward direction.
- **How Calculated**: Count of packets where source and destination match the direction of the first observed packet.
- **Why Useful**: Captures asymmetric traffic behavior (e.g. client uploading bulk vs. downloading bulk).
- **Edge Cases**: Always $\ge 1$ since the first packet is forward.

### 3. `backward_packets`
- **Mathematical Meaning**: Number of packets traveling in the reverse direction.
- **How Calculated**: Count of packets opposite to the first packet's direction.
- **Why Useful**: Distinguishes unidirectional scans/UDP floods from established two-way sessions.
- **Edge Cases**: Equals `0.0` for unidirectional flows.

### 4. `total_bytes`
- **Mathematical Meaning**: Total volume in bytes across all packets in the flow $B = \sum_{i=1}^N L_i$.
- **How Calculated**: Sum of wire lengths of all packets in the flow.
- **Why Useful**: Primary indicator of flow magnitude (e.g. high-volume video/backup vs. low-volume keepalives).
- **Edge Cases**: Non-negative float.

### 5. `forward_bytes`
- **Mathematical Meaning**: Total wire bytes transferred in the forward direction.
- **How Calculated**: Sum of wire lengths for packets with `direction == "FORWARD"`.
- **Why Useful**: Identifies upload volume in encrypted tunnels.
- **Edge Cases**: Defaults to `0.0` if no forward packets.

### 6. `backward_bytes`
- **Mathematical Meaning**: Total wire bytes transferred in the backward direction.
- **How Calculated**: Sum of wire lengths for packets with `direction == "BACKWARD"`.
- **Why Useful**: Identifies download volume in encrypted tunnels.
- **Edge Cases**: Defaults to `0.0` if no backward packets.

### 7. `minimum_packet_size`
- **Mathematical Meaning**: Smallest packet length observed in the flow: $\min(L_1, \dots, L_N)$.
- **How Calculated**: Python `min()` over packet lengths.
- **Why Useful**: Distinguishes protocol control packets (e.g. small TCP ACKs, keepalives, ESP DPD) from payload frames.
- **Edge Cases**: Equals the packet size if $N=1$.

### 8. `maximum_packet_size`
- **Mathematical Meaning**: Largest packet length observed in the flow: $\max(L_1, \dots, L_N)$.
- **How Calculated**: Python `max()` over packet lengths.
- **Why Useful**: Reflects the maximum transmission unit (MTU) utilization and whether bulk segmentation is occurring.
- **Edge Cases**: Equals the packet size if $N=1$.

### 9. `mean_packet_size`
- **Mathematical Meaning**: Arithmetic mean of packet lengths: $\mu_L = \frac{1}{N} \sum_{i=1}^N L_i$.
- **How Calculated**: $\text{total\_bytes} / \text{total\_packets}$.
- **Why Useful**: Key discriminator between interactive keystrokes/SSH (low mean) and video/file transfers (high mean).
- **Edge Cases**: Safe division; defaults to `0.0` if $N=0$.

### 10. `standard_deviation_packet_size`
- **Mathematical Meaning**: Sample standard deviation of packet lengths: $s_L = \sqrt{\frac{1}{N-1}\sum_{i=1}^N (L_i - \mu_L)^2}$.
- **How Calculated**: Standard Bessel's correction applied to packet lengths.
- **Why Useful**: Constant-bitrate voice (VoIP) has very low packet size variance, whereas web browsing has high variance.
- **Edge Cases**: Defaults to `0.0` if $N < 2$.

### 11. `median_packet_size`
- **Mathematical Meaning**: 50th percentile packet length.
- **How Calculated**: Middle value of sorted packet lengths (or average of two middle values if $N$ is even).
- **Why Useful**: Robust against outlier packets (e.g. a single handshake packet in a sea of ACKs).
- **Edge Cases**: Equals packet size if $N=1$.

### 12. `forward_mean_packet_size`
- **Mathematical Meaning**: Average size of packets in the forward direction.
- **How Calculated**: $\text{forward\_bytes} / \text{forward\_packets}$.
- **Why Useful**: Reveals asymmetry in request vs. response payload sizes.
- **Edge Cases**: Defaults to `0.0` if $\text{forward\_packets} = 0$.

### 13. `backward_mean_packet_size`
- **Mathematical Meaning**: Average size of packets in the backward direction.
- **How Calculated**: $\text{backward\_bytes} / \text{backward\_packets}$.
- **Why Useful**: Identifies typical response size from the remote endpoint.
- **Edge Cases**: Defaults to `0.0` if $\text{backward\_packets} = 0$.

### 14. `flow_duration_seconds`
- **Mathematical Meaning**: Total lifespan of the flow: $T_{last} - T_{first}$.
- **How Calculated**: Difference between maximum and minimum packet timestamps in the flow.
- **Why Useful**: Distinguishes ephemeral connections from persistent tunnels or daemon connections.
- **Edge Cases**: `0.0` for single-packet flows or flows where all packets share an identical timestamp.

### 15. `packets_per_second`
- **Mathematical Meaning**: Packet arrival rate: $\lambda = \frac{N}{\Delta T}$.
- **How Calculated**: $\text{total\_packets} / \text{flow\_duration\_seconds}$ if duration $> 0$, else `0.0`.
- **Why Useful**: High values signal automated bursts, denial-of-service, or high-throughput downloads.
- **Edge Cases**: Defaults to `0.0` if duration is `0.0` (avoids division by zero).

### 16. `bytes_per_second`
- **Mathematical Meaning**: Byte throughput: $\Theta = \frac{B}{\Delta T}$.
- **How Calculated**: $\text{total\_bytes} / \text{flow\_duration\_seconds}$ if duration $> 0$, else `0.0`.
- **Why Useful**: Critical for traffic profiling (e.g., video vs audio streaming bandwidth consumption).
- **Edge Cases**: Defaults to `0.0` if duration is `0.0`.

### 17. `mean_inter_arrival_time`
- **Mathematical Meaning**: Average delay between consecutive packets: $\mu_{IAT} = \frac{1}{N-1}\sum_{i=1}^{N-1}(T_{i+1} - T_i)$.
- **How Calculated**: Mean of timestamp deltas across chronologically sorted packets.
- **Why Useful**: Distinguishes human typing pace (hundreds of ms) from machine streaming (sub-millisecond).
- **Edge Cases**: Defaults to `0.0` if $N < 2$.

### 18. `minimum_inter_arrival_time`
- **Mathematical Meaning**: Smallest gap between any two successive packets: $\min(T_{i+1} - T_i)$.
- **How Calculated**: Python `min()` over packet arrival intervals.
- **Why Useful**: Reflects network interface batching, NIC buffering, or back-to-back burst transmissions.
- **Edge Cases**: Defaults to `0.0` if $N < 2$.

### 19. `maximum_inter_arrival_time`
- **Mathematical Meaning**: Largest gap between any two successive packets: $\max(T_{i+1} - T_i)$.
- **How Calculated**: Python `max()` over packet arrival intervals.
- **Why Useful**: Identifies idle intervals, keepalive heartbeat periods, or retransmission timeouts.
- **Edge Cases**: Defaults to `0.0` if $N < 2$.

### 20. `standard_deviation_inter_arrival_time`
- **Mathematical Meaning**: Jitter / variation in packet spacing: $s_{IAT} = \sqrt{\frac{1}{K-1}\sum (IAT_i - \mu_{IAT})^2}$.
- **How Calculated**: Sample standard deviation over the $K = N - 1$ inter-arrival intervals.
- **Why Useful**: Highly periodic traffic (periodic heartbeats) has near-zero IAT stddev, whereas bursty interactive browsing has high IAT stddev.
- **Edge Cases**: Defaults to `0.0` if $N < 3$.

### 21. `forward_packet_ratio`
- **Mathematical Meaning**: Fraction of flow packets in the forward direction: $\frac{N_{fwd}}{N}$.
- **How Calculated**: $\text{forward\_packets} / \text{total\_packets}$.
- **Why Useful**: Normalizes packet directional asymmetry into $[0.0, 1.0]$.
- **Edge Cases**: Defaults to `1.0` if $N=0$.

### 22. `backward_packet_ratio`
- **Mathematical Meaning**: Fraction of flow packets in the backward direction: $\frac{N_{bwd}}{N}$.
- **How Calculated**: $\text{backward\_packets} / \text{total\_packets}$.
- **Why Useful**: Complementary ratio to forward packet ratio ($R_{fwd} + R_{bwd} = 1.0$).
- **Edge Cases**: Defaults to `0.0` if $N=0$ or if all packets are forward.

### 23. `forward_byte_ratio`
- **Mathematical Meaning**: Fraction of total bytes transferred in the forward direction: $\frac{B_{fwd}}{B}$.
- **How Calculated**: $\text{forward\_bytes} / \text{total\_bytes}$.
- **Why Useful**: Distinguishes data sources from data sinks in encrypted channels.
- **Edge Cases**: Defaults to `1.0` if $B=0$.

### 24. `backward_byte_ratio`
- **Mathematical Meaning**: Fraction of total bytes transferred in the backward direction: $\frac{B_{bwd}}{B}$.
- **How Calculated**: $\text{backward\_bytes} / \text{total\_bytes}$.
- **Why Useful**: Measures download skew.
- **Edge Cases**: Defaults to `0.0` if $B=0$ or all bytes are forward.

### 25. `maximum_packets_in_one_second`
- **Mathematical Meaning**: Peak instantaneous packet density within any 1.0-second sliding time window.
- **How Calculated**: A two-pointer sliding window over chronologically sorted packet timestamps:
  $$\max_{i} \Big| \{ j : 0 \le T_j - T_i \le 1.0 \} \Big|$$
- **Why Useful**: Detects sudden traffic bursts (e.g. key renegotiations, TCP window ramps, initial webpage asset loads) even inside long, low-average-rate flows.
- **Edge Cases**: Defaults to `1.0` if $N=1$; `0.0` if $N=0$.
