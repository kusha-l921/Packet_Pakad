# Machine Learning Evaluation Modes and Validation Integrity

## Importance of Evaluation Rigor in Network Traffic Analysis

Evaluating machine learning models on network traffic presents unique data leakage risks. When training and testing packets originate from the same capture session, shared artifacts (e.g., specific hardware timing biases, identical host OS TCP stack parameters, or shared subnet properties) can allow a classifier to achieve artificially inflated accuracy without learning generalizable traffic behaviors.

Phase 3.5 formalizes dataset evaluation into three distinct modes:

## The Three Evaluation Modes

### 1. GROUP_ISOLATED
* **Definition**: Complete partition where training and test flows originate from entirely separate, independent network capture groups (different capture sessions, distinct environments, separate network topologies, or different days).
* **Significance**: Represents the highest validation standard (unseen-capture validation). Accurately simulates real-world deployment where the trained model is presented with unfamiliar traffic from unobserved networks.
* **Interpretation**: Performance metrics under `GROUP_ISOLATED` measure genuine generalization capability and resistance to domain overfitting.

### 2. WITHIN_CAPTURE_HOLDOUT
* **Definition**: Training and test flows are partitioned from within the same underlying capture session or homogeneous environment (e.g., standard random train/test split of flows from a single recording run).
* **Usage Context**: Employed when independent capture diversity is limited or when external benchmark captures lack sufficient group variety.
* **Limitation and Caveat**: `WITHIN_CAPTURE_HOLDOUT` is **not** equivalent to unseen-capture validation. High accuracy in this mode frequently reflects shared environment artifacts rather than robust protocol generalization.

### 3. OVERALL_MIXED_EVALUATION
* **Definition**: Aggregate performance metrics computed across a composite dataset containing a combination of both `GROUP_ISOLATED` and `WITHIN_CAPTURE_HOLDOUT` subsets.
* **Significance**: Provides a blended benchmark summary across the entire available corpus.
* **Essential Limitation**: Downstream reports and technical summaries must explicitly document that mixed evaluation contains within-capture data. It must **never** be cited as evidence of complete unseen-capture validation.

## Known Limitations and Audit Requirements

1. **Leakage Awareness**: Within-capture splits risk feature correlation across flows from the same client session.
2. **Transparent Reporting**: Evaluation summaries generated by the project must always qualify accuracy numbers with the active evaluation mode.
3. **No Overclaiming**: A model achieving 98% under `WITHIN_CAPTURE_HOLDOUT` must not be advertised as having proven 98% real-world generalization.
